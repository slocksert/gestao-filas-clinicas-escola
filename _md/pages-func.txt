Sistema de Gestão de Filas para Atendimento em Clínicas-Escola
Especificação de Funcionalidades (Casos de Uso) — Versão Enxuta
20 casos de uso (reduzido de 33) — consolidação de cadastros e fluxos espelhados; seções "Não se aplica" removidas.
1. Cadastros Base
Os UC-01 a UC-03 abaixo são genéricos e se aplicam às cinco entidades de cadastro base (Paciente, Estudante/Atendente, Supervisor, Sala, Especialidade/Serviço). O que varia entre elas — ator responsável, campos do formulário e regra de duplicidade — está na tabela ao final desta seção.
UC-01 | Cadastrar registro base
Varia por entidade — ver tabela ao final da seção.
Pré-condição
Usuário autenticado com permissão para cadastrar a entidade correspondente.
Fluxo Principal
1. Usuário acessa o menu da entidade desejada.
2. Usuário clica em "Novo [Entidade]".
3. Sistema exibe o formulário de cadastro específico da entidade (ver tabela).
4. Usuário preenche os campos obrigatórios.
5. Usuário clica em "Salvar".
6. Sistema valida os campos obrigatórios.
7. Sistema salva o novo registro.
8. Sistema exibe mensagem de sucesso e retorna à lista.
Fluxo Alternativo
• Usuário clica em "Cancelar" a qualquer momento → sistema descarta os dados e retorna à lista.
Fluxo de Exceção
• Campo obrigatório vazio → sistema exibe mensagem de erro e mantém a tela.
• Registro já cadastrado (para entidades com verificação de duplicidade) → sistema exibe mensagem de duplicidade e não salva.
Pós-condição
Novo registro cadastrado e disponível para uso nos módulos relacionados (triagem, filas, alocação).
UC-02 | Editar registro base
Varia por entidade — mesmo ator responsável pelo cadastro (ver tabela).
Pré-condição
Registro já cadastrado; usuário autenticado com permissão.
Fluxo Principal
1. Usuário acessa a lista da entidade.
2. Usuário seleciona o registro e clica em "Editar".
3. Sistema exibe o formulário preenchido com os dados atuais.
4. Usuário altera os campos desejados.
5. Usuário clica em "Salvar".
6. Sistema valida e atualiza o registro.
7. Sistema exibe mensagem de sucesso.
Fluxo Alternativo
• Usuário clica em "Cancelar" → sistema descarta as alterações e retorna à lista.
Fluxo de Exceção
• Campo obrigatório apagado → sistema exibe mensagem de erro e mantém a tela.
Pós-condição
Cadastro do registro atualizado.
UC-03 | Consultar/listar registros base
Varia por entidade — inclui também perfis de alocação (ex.: atendente responsável pela alocação).
Pré-condição
Usuário autenticado com permissão de consulta.
Fluxo Principal
1. Usuário acessa o menu da entidade.
2. Sistema exibe a lista paginada de registros cadastrados.
3. Usuário aplica filtro relevante à entidade (nome, especialidade, disponibilidade), se desejar.
4. Sistema exibe o resultado filtrado.
Fluxo Alternativo
• Usuário não aplica filtro → sistema mantém a lista completa.
Fluxo de Exceção
• Nenhum resultado encontrado para o filtro → sistema exibe mensagem correspondente.
Pós-condição
Lista de registros exibida conforme critério de busca.
Variações por entidade (UC-01 a UC-03):
UC-04 | Cadastrar perfil de usuário e definir permissões
Administrador do sistema
Pré-condição
Usuário autenticado com permissão administrativa.
Fluxo Principal
1. Usuário acessa o menu "Perfis de Usuário".
2. Usuário clica em "Novo Perfil".
3. Sistema exibe formulário com a lista de operações/módulos disponíveis.
4. Usuário nomeia o perfil e seleciona as permissões correspondentes.
5. Usuário clica em "Salvar".
6. Sistema valida os dados.
7. Sistema salva o perfil.
Fluxo Alternativo
• Usuário clica em "Cancelar" → sistema descarta os dados.
Fluxo de Exceção
• Nome de perfil já existente → sistema exibe mensagem de duplicidade.
Pós-condição
Perfil de usuário criado e disponível para vinculação a usuários do sistema.
2. Triagem e Emissão de Senha
UC-05 | Realizar triagem do paciente
Profissional de triagem
Pré-condição
Paciente cadastrado no sistema; usuário autenticado.
Fluxo Principal
1. Usuário busca o paciente no sistema.
2. Sistema exibe os dados do paciente.
3. Usuário seleciona "Nova Triagem".
4. Sistema exibe o formulário de triagem (motivo do atendimento, especialidade de destino).
5. Usuário preenche o motivo do atendimento e demais dados solicitados.
6. Usuário classifica a prioridade do atendimento.
7. Usuário clica em "Concluir Triagem".
8. Sistema valida os dados obrigatórios.
9. Sistema registra a triagem, tratando os dados de saúde como informação sensível.
10. Sistema encaminha o paciente para emissão de senha.
Fluxo Alternativo
• Paciente enquadrado em prioridade legal (idoso, gestante, PcD) → sistema sinaliza automaticamente a prioridade preferencial.
• Triagem identifica urgência clínica → usuário registra a justificativa e o sistema marca a senha como urgente.
Fluxo de Exceção
• Campo obrigatório não preenchido → sistema exibe mensagem de erro e mantém a tela.
Pós-condição
Triagem registrada e disponível para emissão de senha.
UC-06 | Emitir senha
Profissional de triagem / Sistema
Pré-condição
Triagem concluída para o paciente.
Fluxo Principal
1. Sistema exibe o resumo da triagem realizada.
2. Usuário confirma a emissão da senha.
3. Sistema gera a senha, vinculando-a à especialidade e à classificação de prioridade definida na triagem.
4. Sistema posiciona a senha na fila conforme os critérios de ordenação.
5. Sistema exibe a senha gerada ao usuário/paciente.
Fluxo Alternativo
• Usuário ajusta o tipo de atendimento (primeira consulta, retorno, encaixe) antes de confirmar a emissão.
Fluxo de Exceção
• Especialidade sem fila configurada → sistema exibe erro e impede a emissão da senha.
Pós-condição
Senha emitida com status "aguardando" e inserida na fila correspondente.
UC-07 | Reclassificar prioridade de senha
Profissional de triagem / Supervisor
Pré-condição
Senha emitida e ainda não atendida.
Fluxo Principal
1. Usuário acessa a senha na fila.
2. Usuário seleciona "Reclassificar Prioridade".
3. Sistema solicita o registro de uma justificativa.
4. Usuário informa a justificativa e a nova classificação de prioridade.
5. Usuário confirma a alteração.
6. Sistema atualiza a posição da senha na fila.
7. Sistema registra a alteração para fins de auditoria.
Fluxo de Exceção
• Usuário não informa justificativa → sistema impede a confirmação da reclassificação.
Pós-condição
Senha reposicionada na fila com a nova prioridade e justificativa registradas.
3. Gestão de Fila
UC-08 | Consultar fila e posição de espera
Atendente / Recepcionista / Gestão / Paciente
Pré-condição
Usuário autenticado com permissão de consulta (equipe) ou senha emitida presente na fila (paciente).
Fluxo Principal
1. Equipe acessa o "Painel de Filas" e seleciona a especialidade — ou paciente consulta a senha no sistema/painel.
2. Sistema exibe a lista de senhas aguardando, ordenada por prioridade, horário de chegada e agendamento — ou, para o paciente, calcula e exibe a posição atual e o tempo médio estimado de espera.
3. Equipe aplica filtro adicional por tipo de atendimento (primeira consulta, retorno, encaixe), se desejar.
Fluxo de Exceção
• Fila vazia → sistema exibe mensagem "Nenhuma senha aguardando".
• Dados insuficientes para estimar o tempo → sistema exibe apenas a posição na fila.
Pós-condição
Fila e/ou posição/tempo estimado exibidos conforme o critério e o ator.
4. Chamada e Alocação de Recursos
UC-09 | Chamar próxima senha
Atendente / Recepcionista
Pré-condição
Existe ao menos uma senha com status "aguardando" na fila da especialidade.
Fluxo Principal
1. Usuário acessa o "Painel de Filas".
2. Usuário clica em "Chamar Próxima".
3. Sistema identifica a próxima senha conforme os critérios de ordenação da fila.
4. Sistema exibe a chamada (paciente, senha) no painel público.
5. Usuário confirma a chamada.
6. Sistema atualiza o status da senha para "chamada".
Fluxo Alternativo
• Existe senha marcada como urgência clínica → sistema a prioriza automaticamente sobre as demais.
Fluxo de Exceção
• Paciente não comparece dentro do prazo de tolerância → sistema retorna a senha à fila ou a marca como ausente.
Pós-condição
Senha com status "chamada", exibida no painel público de atendimento.
UC-10 | Alocar recursos ao atendimento (estudante, supervisor e sala)
Atendente / Sistema
Pré-condição
Senha com status "chamada".
Fluxo Principal
1. Sistema verifica a disponibilidade e a compatibilidade do estudante/atendente com o atendimento.
2. Sistema verifica a disponibilidade do supervisor e o limite de estudantes supervisionados.
3. Sistema verifica a disponibilidade e a compatibilidade da sala.
4. Sistema associa estudante, supervisor e sala à senha.
5. Usuário confirma a alocação.
6. Sistema registra o vínculo do atendimento aos recursos alocados.
Fluxo Alternativo
• Atendimento não exige supervisão docente → sistema não realiza a verificação de supervisor e segue para a verificação de sala.
Fluxo de Exceção
• Nenhum supervisor disponível para a especialidade → sistema bloqueia novas chamadas para a especialidade e notifica a gestão.
• Nenhuma sala compatível disponível → sistema mantém a senha aguardando alocação de recurso.
Pós-condição
Estudante, supervisor e sala alocados e vinculados ao atendimento.
5. Atendimento
UC-11 | Iniciar atendimento
Estudante/Atendente
Pré-condição
Recursos (estudante, supervisor, sala) alocados à senha.
Fluxo Principal
1. Usuário acessa a senha alocada.
2. Usuário clica em "Iniciar Atendimento".
3. Sistema registra o horário de início.
4. Sistema atualiza o status para "em atendimento".
Fluxo de Exceção
• Recurso alocado não está mais disponível no momento do início → sistema impede o início e solicita nova alocação.
Pós-condição
Atendimento em andamento, com horário de início registrado.
UC-12 | Pausar / retomar atendimento
Estudante/Atendente
Pré-condição
Atendimento em andamento (para pausar) ou pausado (para retomar).
Fluxo Principal
1. Pausar: usuário clica em "Pausar Atendimento".
2. Sistema solicita o motivo da pausa; usuário informa.
3. Sistema registra a pausa e o horário, atualizando o status para "pausado".
4. Retomar: usuário acessa o atendimento pausado e clica em "Retomar".
5. Sistema registra o horário de retomada e atualiza o status para "em atendimento".
Fluxo de Exceção
• Motivo não informado, quando exigido pelo protocolo → sistema impede a confirmação da pausa.
• Sala ou estudante originalmente alocados não estão mais disponíveis na retomada → sistema solicita nova alocação de recurso.
Pós-condição
Atendimento pausado (com motivo registrado) ou retomado (status "em atendimento"), conforme a ação.
UC-13 | Encerrar atendimento
Estudante/Atendente / Supervisor
Pré-condição
Atendimento com status "em atendimento".
Fluxo Principal
1. Usuário clica em "Encerrar Atendimento".
2. Sistema solicita o registro do desfecho (alta, retorno agendado, encaminhamento interno ou externo).
3. Usuário informa o desfecho.
4. Sistema verifica se o protocolo do serviço exige validação do supervisor.
5. Supervisor valida o encerramento, quando exigido.
6. Sistema registra o horário de encerramento.
7. Sistema atualiza o status para "encerrado".
Fluxo Alternativo
• Protocolo do serviço não exige validação de supervisor → sistema conclui o encerramento sem a etapa de validação.
Fluxo de Exceção
• Supervisor não valida ou recusa o encerramento → sistema mantém o atendimento com status "pendente de validação".
Pós-condição
Atendimento encerrado (ou pendente de validação do supervisor), com desfecho registrado.
6. Encaminhamento
UC-14 | Registrar encaminhamento interno
Estudante/Atendente / Supervisor
Pré-condição
Atendimento encerrado com desfecho "encaminhamento interno".
Fluxo Principal
1. Usuário seleciona a especialidade de destino.
2. Sistema valida se a especialidade está ativa.
3. Usuário confirma o encaminhamento.
4. Sistema gera uma nova entrada de fila vinculada ao atendimento original.
5. Sistema registra o encaminhamento.
Fluxo de Exceção
• Especialidade de destino inexistente ou inativa → sistema exibe mensagem de erro e impede o encaminhamento.
Pós-condição
Nova entrada de fila criada na especialidade de destino, vinculada ao atendimento original.
UC-15 | Registrar encaminhamento externo
Estudante/Atendente / Supervisor
Pré-condição
Atendimento encerrado com desfecho "encaminhamento externo".
Fluxo Principal
1. Usuário informa os dados do encaminhamento externo (instituição/serviço de destino, motivo).
2. Usuário confirma o registro.
3. Sistema registra o encaminhamento externo, sem gerar nova entrada de fila.
Fluxo de Exceção
• Dados obrigatórios não preenchidos → sistema exibe mensagem de erro.
Pós-condição
Encaminhamento externo registrado e vinculado ao atendimento original.
7. Ausências e Desistências
UC-16 | Registrar ausência (no-show)
Sistema / Atendente
Pré-condição
Senha chamada e prazo de tolerância expirado sem comparecimento do paciente.
Fluxo Principal
1. Sistema identifica que o prazo de tolerância da senha chamada expirou.
2. Sistema marca a senha com status "ausente".
3. Sistema libera os recursos alocados para o próximo atendimento da fila.
4. Sistema registra a ausência no histórico do paciente.
Fluxo Alternativo
• Usuário marca a ausência manualmente, antes do prazo de tolerância expirar.
Fluxo de Exceção
• Paciente atinge o número de reincidências definido em política → sistema aplica restrição temporária ou exige confirmação prévia para novos agendamentos.
Pós-condição
Senha marcada como ausente; recursos alocados liberados para novo atendimento.
UC-17 | Registrar desistência voluntária
Atendente / Paciente
Pré-condição
Senha com status "aguardando" ou "em atendimento".
Fluxo Principal
1. Paciente ou usuário solicita a desistência do atendimento.
2. Sistema solicita o motivo da desistência (opcional).
3. Usuário informa o motivo, caso deseje.
4. Sistema registra a desistência, distinguindo-a de uma ausência.
5. Sistema remove a senha da fila ativa.
Pós-condição
Senha com status "desistência"; recursos eventualmente alocados são liberados.
8. Indicadores, Alertas e Auditoria
UC-18 | Consultar indicadores de atendimento
Gestão da unidade
Pré-condição
Usuário autenticado com permissão de gestão.
Fluxo Principal
1. Usuário acessa o menu "Indicadores".
2. Usuário seleciona o período e a especialidade desejados.
3. Sistema calcula e exibe os indicadores (tempo médio de espera, tempo médio de atendimento, taxa de ausência, volume de atendimentos).
Fluxo de Exceção
• Não há dados suficientes no período selecionado → sistema exibe mensagem "Sem dados disponíveis".
Pós-condição
Indicadores exibidos conforme o filtro selecionado.
UC-19 | Visualizar alertas de SLA
Gestão da unidade
Pré-condição
Existe fila com tempo de espera sendo monitorado pelo sistema.
Fluxo Principal
1. Sistema monitora continuamente o tempo de espera das filas ativas.
2. Sistema identifica fila com tempo de espera acima do limite definido (SLA).
3. Sistema gera um alerta e notifica a gestão da unidade.
4. Usuário (gestor) visualiza o alerta no painel de gestão.
Fluxo Alternativo
• Gestor aciona medida de escalonamento (reforço de atendente, abertura de vaga extra) a partir do alerta.
Pós-condição
Alerta de SLA emitido e visível à gestão da unidade.
UC-20 | Consultar trilha de auditoria
Administrador do sistema / Gestão
Pré-condição
Usuário autenticado com permissão de auditoria.
Fluxo Principal
1. Usuário acessa o menu "Auditoria".
2. Usuário aplica filtros (usuário, período, tipo de operação).
3. Sistema exibe os registros de auditoria correspondentes ao filtro.
Fluxo de Exceção
• Nenhum registro encontrado para o filtro aplicado → sistema exibe mensagem correspondente.
Pós-condição
Registros de auditoria exibidos conforme o filtro selecionado.*
